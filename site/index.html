01 / THE PROJECT

Bringing a classic
language forward.

GFA BASIC was part of the creative computing era of the Amiga. This project explores a careful, evidence-led way to compile its 3.5 dialect into native programs — without pretending that the hard compatibility work is already done.

01

Faithful by evidence

Language rules are tied to version-specific references. Uncertain behavior stays explicitly unresolved.

02

Native by design

The target is Linux x86-64. LLVM is the planned production backend; the current C bridge is temporary.

03

Rust throughout

A modular compiler, generated-program runtime and platform layer form the planned foundation.

02 / WHAT WORKS TODAY

A small step.
A real executable.

The experimental frontend accepts a deliberately narrow, documented subset: literal FACT, VARIAT and COMBIN assignments followed by PRINT. It verifies typed project IR before using a temporary C/cc bootstrap.

Build instructions in the README ↗
SUPPORTED SHAPE · ILLUSTRATIVE
x = FACT(5)
PRINT x
BUILD OUTPUT Native executable
!

The current prototype demonstrates a deliberately limited subset; it is not general GFA BASIC support and does not claim compatibility with the original interpreter. Variables are limited to x, y and z, with no reassignment. Arguments must be integer literals: FACT(n) accepts 0–20, while VARIAT(n,k) and COMBIN(n,k) accept 0 ≤ k ≤ n ≤ 20. These are prototype limits, not limits of the GFA BASIC language. General language semantics, the production IR, LLVM backend and runtime remain unimplemented.

03 / DEVELOPER TOOLS

Early tools.
Explicit boundaries.

IMPLEMENTED SUBSET

Source formatter

The gfabasic fmt library and CLI format only the currently supported FACT, VARIAT, COMBIN and PRINT syntax. Unsupported syntax is rejected; this is not yet a general GFA BASIC formatter.

↗
INITIAL LSP

Language server

The standalone LSP adapter supports document open/change/close and parser diagnostics. Formatting integration, navigation, completion and rename are not implemented.

↗
PROJECT STATUS

Research before claims

Language rules remain evidence-gated against the Amiga 3.5 references. The implemented editor tools do not imply full language parsing or conformance.
