Architecture Decision Record

ADR NNNN: Title

  • Status: Proposed | Accepted | Superseded | Rejected
  • Date: YYYY-MM-DD
  • Decision makers: Project maintainers

Context

Describe the problem, constraints, evidence, and consequences of leaving the question unresolved.

Decision drivers

List the criteria that matter to this decision, in priority order where trade-offs require ranking. Include constraints that alternatives must satisfy. If there are no meaningful drivers beyond the context, state that explicitly.

Decision

State the decision in direct, testable terms. Mark any part that remains provisional.

Alternatives considered

List realistic alternatives and compare them against the decision drivers. Explain why each was accepted or rejected; state "None" if no viable alternative was considered.

Consequences

Describe positive and negative consequences, migration implications, and follow-up work.

Risks and mitigations

List material risks introduced or left unresolved by the decision and practical mitigations or monitoring. State "None identified" when appropriate.

Implementation status

  • Status: Not started | Partial | Implemented | Deferred | Not applicable
  • Evidence / tracking: Link implementation commits, tests, or issues; explain what remains. Do not infer implementation completion from an Accepted decision.

Review triggers

Name concrete events, evidence, or changed assumptions that should cause this decision to be revisited. State "None identified" only when no foreseeable trigger applies.

Evidence and references

List primary references, versions, page/section identifiers, implementation evidence, and unresolved uncertainty.

Supersedes / superseded by

Link related ADRs when applicable.
